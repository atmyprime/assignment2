4. Mention two reasons why branches are used in a Git repository.

Branches allow developers to work on new features or changes without affecting the main working version of the project. They also allow multiple developers to work on different parts of a project at the same time and later merge their changes together.


5. What is the difference between git log and git status?

git log displays the history of commits that have already been made to the repository. git status shows the current state of the working directory and staging area, including modified, staged, and untracked files.

8. In the context of object-oriented programming:
(I) What is inheritance?
(II) What is polymorphism?
(III) What is encapsulation?

Inheritance is when a class receives attributes and methods from another class. This makes it possible to reuse existing code and create more specialized classes.

Polymorphism is the ability for the same method or interface to behave differently depending on the object or class that is using it.

Encapsulation is the practice of keeping an object's data and the methods that work with that data together inside a class while controlling access to the internal data.


9. What is the main difference between the "Dictator and Lieutenants" workflow and the "Integration Manager" workflow?

The Integration Manager workflow has developers push their work to their own public repositories, and an integration manager is responsible for integrating those changes into the main or blessed repository and resolving conflicts. The Dictator and Lieutenants workflow adds another level. Developers send their changes to lieutenants, the lieutenants combine changes from groups of developers, and the dictator combines the lieutenant repositories into the central repository. Only the dictator pushes to the central repository.


10. How would a team of 100 developers benefit from following the "Dictator and Lieutenants" workflow instead of the "Centralized" workflow?

A team of 100 developers would benefit because the work of integrating changes and resolving conflicts can be divided among several lieutenants instead of having all developers work directly with one central repository. Each lieutenant can manage a smaller group of developers, and the dictator only has to deal with the integrated work from the lieutenants. This reduces bottlenecks and makes a very large development team easier to manage.
